# LEO v1.1.0 frozen experiment design

This directory is the R4 experiment-design freeze for the repaired LEO reconstruction.

## Scope

`primary_static_source_constrained` is the primary confirmatory dataset for the repaired implementation. It is deliberately described as a **source-constrained reconstruction**, not an exact replay of the original authors' unpublished simulator files, coordinates, or scenario grid.

The primary design is balanced over:

- six reconstructed Fig. 4 layout shapes;
- environmental factors 2.0, 2.25, 2.5, 2.625, 3.0;
- ordinary conditions for every layout plus a separately identified triangle-interference condition;
- relay caps 1, 2, and 3 as separate strata because the source does not publish the cap and the historical result is cap-sensitive;
- hop-count, generic LQI, literal LQI, and LEO;
- 20 repetitions from seed base 42;
- static nodes only.

The primary design uses literal transcribed Eq. 17 (`boundEq17ToRMax=false`) and keeps the historical bounded policy as a mandatory sensitivity. This is a reconstruction decision, not a claim about the original authors' implementation.

The primary energy-accounting mode is the simplified reconstruction proxy. The datasheet-anchored nRF52840 RADIO-current model is a mandatory, separately stratified sensitivity.

## Separation of experiment sets

The manifest keeps five distinct sets:

1. `primary_static_source_constrained` — primary static reconstruction.
2. `eq17_bounded_sensitivity` — bounded-vs-literal Eq. 17 sensitivity.
3. `nrf52840_energy_sensitivity` — energy-accounting sensitivity.
4. `reconstruction_ofat_sensitivity` — one-factor-at-a-time checks of unpublished reconstruction constants.
5. `mobility_extension` — exploratory mobility only; never pooled into source-reproduction claims.

## Analysis freeze

The primary analysis must pair metrics by exact scenario/run identity, retain `interference` and `relayCap` as explicit strata, never use observed outcomes to decide whether a scenario enters the primary analysis, never infer route identity from exact equality of total energy, use the direct per-ping route fingerprint/hop-count evidence, and define multiplicity handling in R6 before final inferential claims.

## Provenance

`manifest.json` is the human/machine-readable design authority. `frozen_plan.jsonl` is a deterministic expansion into configuration-level argv records generated by `expand_manifest.py` and checked by `validate_plan.py`.

Every R5 raw and route-evidence row must carry the SHA-256 of the frozen manifest.

R4 does not authorize production execution. R5 may execute this plan only after the R4 closeout is frozen.
